# Сценарий: установка claude-box на VDS (профиль server)

> Для агента на Mac. Запуск: в чате с агентом — «проект claude-box: выполни prompts/INSTALL_VDS.md».
> Код — твоя рабочая копия `/workspace/claude-box`. Сначала прочитай `README.md` (и `CLAUDE.md`, если он есть).

## Правила
- Все команды на сервере — `ssh <сервер> '<команда>'`; каждая требует подтверждения пользователя.
  Перед каждой коротко объясни, что она делает. Однотипные шаги объединяй.
- **На сервере уже работают чужие контейнеры** (VPN, другой экземпляр Claude Code). Ничего из них не
  останавливай, не пересоздавай и не меняй. `systemctl restart docker` и перезагрузка сервера перезапустят
  и их — только с явного согласия пользователя.
- **Спроси пользователя перед**: установкой Docker, созданием swap, изменением sshd или правил файрвола,
  не относящихся к claude-box, удалением чего-либо.
- Не ослабляй защиту, чтобы «заработало». Не прошла проверка — найди причину и покажи диагностику.
- Секреты (`SOCKS_PASS`, `TTYD_PASSWORD`, содержимое `.env`) не выводи целиком.
- Если на Mac claude-box старше 1.0, его хук не требует подтверждения для SSH к серверам — подтверждения
  будут только обычными запросами Claude Code. Предупреди пользователя: не выбирать «Yes, and don't ask again»
  для `ssh`. Начиная с 1.0 это правило закреплено политикой.
- Сборка долгая (5–15 минут): запускай установщик с `--detach` и читай `install.log`, а не жди в одной команде.

## Фаза 0. Вопросы пользователю (одним сообщением)
1. Адрес сервера, порт SSH и пользователь. Для агента на сервере нужен пользователь хоста с правами на Docker
   (в группе `docker` или root) — от его имени агент будет выполнять `ssh host '…'`.
2. Прокси для сервера: тот же, что на Mac, или другой. Данные прокси пользователь впишет в `.env` на сервере
   сам (рекомендуется) или передаст тебе.
3. Нужен ли браузер на сервере (решим после проверки ресурсов).
4. Пропускает ли прокси SSH (порт сервера). Если нет — IP сервера нужно добавить в `DIRECT_CIDRS` на Mac
   (это делает пользователь, ты только подскажи).

## Фаза 1. Доступ
- Покажи свой публичный ключ (`cat ~/.ssh/id_ed25519.pub`); пользователь добавит его в `~/.ssh/authorized_keys`
  на сервере.
- Подключайся `ssh -p <порт> <user>@<ip> '…'`. Если в `.env` Mac есть `SSH_HOSTS` с алиасом `vds` —
  используй `ssh vds`.
- Проверка: `ssh … 'uname -a; id; docker version --format "{{.Server.Version}}"; docker ps --format "{{.Names}}"'`.
  Покажи список чужих контейнеров — чтобы было видно, что ты их не трогаешь.

## Фаза 2. Код и проверка системы
- Папка: `/opt/claude-box` (если есть sudo) или `~/claude-box`. **Не внутри** будущей рабочей папки агента.
- Код: `rsync -az --no-owner --no-group --delete --exclude .env --exclude install.log --exclude '.backup/' --exclude 'report-*' --exclude 'tests/.tmp/' --exclude /CLAUDE.md --exclude /START.md --exclude /docs/ /workspace/claude-box/ <сервер>:<папка>/`
  (локальные рабочие файлы агента — `CLAUDE.md`, `START.md`, `docs/` — на сервер не нужны).
  `--no-owner --no-group` обязательны: без них файлы получат uid агента из контейнера (1000), и любой
  пользователь хоста с этим uid сможет менять `install.sh`, который запускает root. Проверка:
  `ssh … 'find <папка> ! -user $(id -un) | wc -l'` → 0.
- Если репозиторий публичный или у сервера есть к нему доступ — после rsync переключи `origin` на HTTPS
  (`git remote set-url origin https://github.com/<владелец>/claude-box.git && git config --unset core.sshCommand`):
  тогда сервер обновляется сам (`./install.sh --update`, в том числе из агента на сервере через `ssh host`).
- `ssh … 'cd <папка> && ./install.sh --check --profile server'` (+ `--browser`, если пользователь хочет браузер).
  Покажи итог. Ошибки (TUN, Docker, порты, имена, подсети) — разбери с пользователем до установки.
  Конфликт имён с чужим контейнером — `BOX_PREFIX=cbox` в `.env`; конфликт подсети — другая `DOCKER_SUBNET`.

## Фаза 3. Установка
- `.env`: `ssh … 'cd <папка> && cp -n .env.example .env && chmod 600 .env'`, затем пользователь вписывает
  `SOCKS_HOST/PORT/USER/PASS` (или ты — данными, которые он дал). Остальное заполнит установщик
  (`HOST_SSH_USER` — пользователь из фазы 0).
- `ssh … 'cd <папка> && ./install.sh --yes --profile server --detach'` — в фоне; ход: `ssh … 'tail -n 40 <папка>/install.log'`
  раз в 1–2 минуты, пока не появится «Готово» или ошибка.
  `--yes` означает: добавить ключ агента в `authorized_keys` пользователя хоста (с `restrict,pty`),
  правило ufw для SSH из сети claude-box (если ufw включён), systemd-юнит `claude-box-firewall`.
  Скажи это пользователю до запуска.

## Фаза 4. Проверки
1. В `install.log`: шлюз `healthy`, строка `geo:`, leak-test без ✘ (в том числе «изменения через docker-ro запрещены»).
2. Порты только на 127.0.0.1: `ssh … 'ss -ltnp | grep -E ":(7681|6080)"'`.
3. IP агента = IP прокси и ≠ IP сервера: `docker exec <префикс>-agent curl -s https://api.ipify.org` против `curl -s https://api.ipify.org` на хосте.
4. Kill-switch: `docker exec <префикс>-gateway sh -c 'pkill -x sing-box; sleep 0.5; curl -s --max-time 2 https://1.1.1.1/cdn-cgi/trace && echo LEAK || echo BLOCKED'`
   — ожидается `BLOCKED`; через ~10 с шлюз снова healthy.
5. Агент видит Docker только на чтение: `docker exec -u agent <префикс>-agent bash -lc 'docker ps --format "{{.Names}}" | head'`.
6. `./install.sh --report` — сохрани вывод в `/workspace/_reports/` (пароли в нём замаскированы).

## Фаза 5. Передача пользователю
- Как зайти в терминал агента на сервере: `ssh -t <сервер> docker exec -it -u agent <префикс>-agent tmux attach -t main`
  или туннель `ssh -N -L 17681:127.0.0.1:7681 <сервер>` → http://localhost:17681 (пароль — `TTYD_PASSWORD` в `.env` на сервере).
- Первый вход: `/login` в окне `claude` (ссылку пользователь открывает у себя, код вставляет обратно); в окне `rc`
  один раз ответить `y`. После этого «claude-box-vds» появится в приложении Claude.
- Обновление в будущем: `git push`, затем `ssh … 'cd <папка> && ./install.sh --update --detach'` (git pull с GitHub);
  если `origin` на сервере недоступен — rsync кода (флаги из фазы 2) + `./install.sh --update --no-pull --detach`.
- Если по ходу менялся код — запись в `CHANGELOG.md`, патч-версия в `VERSION`, коммит.
