# Изменения

## 1.0.5 — 2026-11-19
- **Маски диска Mac: копии `.env` и ключ OrbStack** `[security]`. `gen-mac-mounts.sh` закрывал только `.env`
  установки, а копии, которые `install.sh` при каждом запуске кладёт в `.backup/<время>/.env` (пароли прокси,
  веб-терминала, noVNC), оставались видны агенту в `/mac/home`. Теперь закрыты `.backup` установки (каталог
  создаётся заранее — точку монтирования в `/mac/home` только для чтения Docker создать не может),
  `~/.orbstack/ssh` (закрытый ключ OrbStack) и `~/.Trash` (туда попадают старые установки вместе с `.env`).
- leak-test: проверяет `~/.orbstack/ssh` и ищет видимые агенту копии `.env` claude-box (по `SOCKS_HOST`/`SOCKS_PASS`,
  на два уровня вглубь домашней папки, включая `.backup` и старые установки). Содержимое не выводится.
- `run-all.sh`: маски `gen-mac-mounts.sh` на поддельной домашней папке.
- `install.sh`: после пересоздания шлюза агент и браузер пересоздаются повторно только если compose сам не
  подключил их к новому шлюзу. Раньше — всегда, то есть при каждом обновлении агент, Remote Control и чаты
  перезапускались дважды.
- `install.sh`: на Mac нет ложного «RAM … рекомендуется 4000 МБ» для VM на 4 ГБ (рекомендация сверяется
  с допуском 5%) и «+swap 0 МБ» (swap внутри VM Docker установщик не измеряет).

## 1.0.4 — 2026-11-19
- `--force` запоминается в `.env` (`FORCE_RESOURCES=1`). Раньше на слабом сервере каждое `./install.sh --update`
  (и самообновление из агента) останавливалось на той же нехватке RAM/диска, которую пользователь уже принял
  при установке. Отменить — убрать ключ из `.env`. `--check` ключ учитывает, но не записывает.
- `run-all.sh`: `--force` записывается и учитывается повторным запуском; без `--force` не включается.

## 1.0.3 — 2026-11-19
- **noVNC (6080) публикуется только с браузером** `[security]`. Раньше шлюз всегда публиковал 6080 (на 127.0.0.1),
  даже при `BROWSER=0`, — лишний открытый порт и занятый номер на хосте. Теперь порт — в
  `docker-compose.browser.yml`, а `install.sh` пишет в `.env` `COMPOSE_FILE`: основной файл, плюс файл браузера
  при `BROWSER=1`, плюс `docker-compose.override.yml`, если он есть (при заданном `COMPOSE_FILE` compose сам его
  не подхватывает — без этого на Mac пропал бы диск `/mac/home`). Проверка занятости 6080 — только с браузером.
- `run-all.sh`: 6080 только в файле браузера; `COMPOSE_FILE` без браузера, с браузером и с override.

## 1.0.2 — 2026-11-19
Первая живая установка профиля `server` на VDS (Ubuntu 24.04, x86_64, Docker 28.5): установка, leak-test,
kill-switch, docker-ro — без ошибок.
- `prompts/INSTALL_VDS.md`: rsync кода на сервер — с `--no-owner --no-group`. Без них папка установки
  принадлежала uid агента из контейнера (1000), и пользователь хоста с этим uid мог бы менять `install.sh`,
  который запускает root; git под root к тому же отказывался работать («dubious ownership»).
- `prompts/INSTALL_VDS.md`: после rsync `origin` на сервере — HTTPS-адрес репозитория, обновление — `./install.sh --update`.

## 1.0.1 — 2026-11-19
- `tests/install-dryrun.sh` больше не зависит от машины, на которой его запускают: заглушки `ss` и `ip`,
  путь к TUN — через `CB_TEST_TUN_DEV` (только для тестов; `install.sh` предупреждает, если она задана).
  Раньше в контейнере агента обычная установка падала, а проверка конфликта проходила вхолостую.
- `run-all.sh`: проверка предупреждения о `CB_TEST_TUN_DEV`.
- `__pycache__` убран из репозитория и добавлен в `.gitignore`.

## 1.0.0 — 2026-11-19
Единый репозиторий вместо двух пакетов (`claude-box-mac` и облегчённого `server/`).

- **Один `install.sh`** для Mac и Linux: профили `mac`/`server` (только умолчания), флаги `--browser`,
  `--docker ro|0`, `--host-access`, `--yes`, `--force`; `--check` (проверка системы без изменений),
  `--update [--detach]`, `--report` (диагностика с замаскированными паролями), журнал `install.log`.
- **Проверка системы**: ОС и архитектура, виртуализация (OpenVZ/LXC), `/dev/net/tun`, версии Docker и compose,
  RAM и диск (минимумы с браузером и без), занятые порты, чужие контейнеры с теми же именами, пересечение
  подсетей с сетями Docker и маршрутами хоста, sshd/«Удалённый вход», доступность прокси.
- **docker-ro** `[security]`: Docker API хоста только для чтения (свой фильтр: GET по белому списку, без
  archive/export/exec, один запрос на соединение). Агент смотрит `docker ps/logs/inspect/stats` без
  подтверждений; изменения — `ssh host 'docker …'` с подтверждением.
- **host-guard** `[security]`: подтверждение для любого SSH (не только к Mac) и для обращений к хосту;
  `docker run/compose up/...` через CLI контейнера — отказ с подсказкой; прямые SSH-цели в локальной сети —
  отказ; скрипты и tmux-обёртки с SSH — подтверждение. Managed-правила `ask`: `ssh`, `scp`, `sftp`, `rsync *:*`.
- **Правила агента под профиль**: `/etc/claude-code/CLAUDE.md` собирается при старте из частей
  (`agent/claude/md/`): Mac, сервер, без доступа к хосту, браузер, Docker.
- **SSH_HOSTS** в `.env`: алиасы других серверов для агента (`vds=root@ip:22`), с подтверждением.
- Имена контейнеров и проекта из `.env` (`BOX_PREFIX`, `COMPOSE_PROJECT_NAME`, `BOX_HOSTNAME`), чтобы ставить
  рядом с чужими контейнерами; `PUID=0` запрещён; установка внутри рабочей папки агента запрещена.
- `host-firewall.sh`: трафик внутри подсети claude-box (шлюз ↔ docker-ro) не режется; юнит ставит install.sh
  с реальным путём.
- `tests/`: проверки без Docker (`bash tests/run-all.sh`).
- Сценарий для агента: `prompts/INSTALL_VDS.md` (установка на сервер).
